# 字幕翻译
---

**0:00 – 0:14** 我们将深入了解技能的结构与创建最佳实践，并通过两个示例加以应用：一个是根据讲义生成练习题，另一个是分析时间序列数据的特征。

---

**0:15 – 0:52** 本课将聚焦于技能的结构与最佳实践，并通过技能创建器运行两个自制技能，检验其是否符合规范。每个技能都需要一个包含 YAML 前置元数据的 SKILL.md 文件，其中必须包含名称和描述。正文包含技能内容，以及对脚本、文本文件或其他资源的引用，这些仅在需要时才加载。

---

**0:53 – 1:32** 名称和描述至关重要——它们不仅帮助 Claude 理解技能的功能，也决定了何时触发该技能。名称有字符数限制，只能包含小写字母、数字和连字符，建议采用"动词+ing+技能名称"的格式。描述要说明技能的功能和使用时机，并点明能触发该技能的关键词。

---

**1:33 – 2:07** 除必填字段外，代理技能规范还支持可选字段，如许可证、兼容性及元数据键值对。需要注意的是，规范仍在活跃开发中，实际遇到的一些技能（包括 Anthropic 官方的）可能并不完全遵循该规范，这在多模型提供商和代理工具生态系统的协作中是正常现象。

---

**2:08 – 2:52** SKILL.md 正文格式没有强制限制，但为构建可预测的工作流，建议提供逐步说明、明确边界情况，并说明可跳过某步骤的原因。保持在 500 行以内是最佳实践，超出部分可通过引用外部文件处理。简洁清晰非常重要，路径务必使用正斜杠，以确保跨平台兼容性。

---

**2:53 – 3:43** 创建技能时需考虑自由度：遵循最佳实践的场景应给予较低自由度；需要创意输出（如多种颜色、风格、字体）的场景则可给予较高自由度。对于包含多个技能的复杂工作流，拆分为顺序步骤始终优于单一庞大的"万能"技能。系统可处理 100 个以上的技能，命名要清晰、不易混淆，并遵循可预测的模式。

---

**3:43 – 4:21** 规范支持可选目录，常见子文件夹包括：**scripts**（需读取和执行的代码，需包含错误处理和文档）、**references**（额外的文档或参考文件，较长的文件建议指示完整读取）、**assets**（输出模板、图片、Logo、数据文件、Schema 等）。这些目录名遵循代理技能标准，但实际遇到的技能可能使用不同约定，因为标准仍在快速演进中。

---

**4:45 – 6:02** 第一个技能是"生成练习题"，用于根据讲义生成教育性练习题以测试理解程度。技能中指定了输入格式、要使用的库和要提取的文本，并明确规定了题目生成顺序：从判断题开始，逐步推进到实际应用题，每类题目都附有子指南，整个文件不超过 500 行。

---

**6:02 – 7:44** 在输出格式方面，该技能通过引用 assets 文件夹中的模板来指定 Markdown 和 LaTeX 等格式的输出样式，而非在 SKILL.md 中直接内嵌所有示例。这些模板文件只在需要时才加载，可高效利用 Token 和上下文窗口。同样，领域特定的参考资料也放在 references 文件夹中，体现了"渐进式披露"理念——只在需要时加载必要内容。

---

**7:45 – 9:11** 第二个技能是"分析时间序列数据"，用户提供 CSV 文件，技能在预测前先分析数据特征，具有明确的确定性工作流，依赖多个 Python 脚本。包括可视化脚本（时间序列图、直方图、滚动统计、箱线图等）、自相关与分解图脚本，以及 diagnose.py（依次分析数据质量、分布、平稳性、季节性、趋势、自相关，最后给出变换建议）。整个工作流每次都按固定顺序执行。

---

**9:11 – 9:47** 该技能明确规定了输入格式（列名和数据类型），在工作流部分逐步指定运行脚本的顺序，包括生成图表的可选步骤、汇报数据、读取 summary.txt 并展示相关图表，以及通过 interpretation.md 解读分析结果。同时列明了脚本的额外参数选项和输出文件树结构，并明确了所有 Python 依赖项。

---

**9:47 – 11:25** 接下来通过 Claude Code 运行技能创建器来评估这两个技能。与 Claude AI 不同，Claude Code 不内置技能创建器，需通过 anthropic/skills 市场安装（包含 document-skills 和 example-skills 两个集合）。安装并重启后，使用 /skills 命令确认 skill-creator 就绪，随后并行启动两个子代理分别评估两个技能。结果："生成练习题"得 9/10 分，简洁性有改进空间；"分析时间序列"表现更佳，在避免重复、前置元数据质量和简洁性方面均表现出色。

---

**11:25 – 13:01** 除了检查最佳实践，还需验证技能是否按预期工作，方法类似于软件单元测试。对于"生成练习题"，测试内容包括：生成并保存为 Markdown、LaTeX、PDF 格式，验证文件格式、PDF 处理库、学习目标提取、各类题目生成规范、输出模板使用及 LaTeX 编译成功与否，最后收集人工反馈并在所有目标模型上测试。

---

**13:01 – 16:10** 对于"分析时间序列"，假设三个 Python 脚本已通过传统单元测试，重点测试整体流程：步骤顺序、输入输出是否符合预期、可选图表步骤是否执行、摘要返回与结果解读，以及最终输出文件夹结构是否正确。同样需要人工反馈和多模型测试。下一课将把这两个技能带入 Jupyter Notebook，通过 Claude Messages API 以编程方式运行并生成输出。

# 关于自由度

- 如果需要遵循最佳实践，我们就需要用`low freedom`。反之，需要有更多创造性的输出，多种颜色，多种样式，多种字体，我们就需要允许使用`high freedom`
	
- 当我们开始考虑使用多种技能的更复杂的工作流时，将事情分解成连续的步骤总是比使用一个非常非常大的技能来尝试完成所有工作更有价值。
