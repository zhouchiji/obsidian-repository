# Skills 详解：Skills 与提示词、Projects、MCP 及子智能体的比较

> 原文：[Skills explained: How Skills compares to prompts, Projects, MCP, and subagents](https://claude.com/blog/skills-explained)
> 发布日期：2025 年 11 月 13 日 | 阅读时间：约 5 分钟

Skills 是构建自定义 AI 工作流和智能体的强大工具，但它在 Claude 技术栈中处于什么位置？本文将解释各工具的适用时机，以及它们如何协同工作。

---

## 理解你的智能体构建模块

### 什么是 Skills？

Skills 是包含指令、脚本和资源的文件夹，Claude 会在遇到相关任务时动态发现并加载它们。可以把它们想象成专业的培训手册，赋予 Claude 在特定领域的专业能力——从处理 Excel 电子表格到遵循组织的品牌规范。

**Skills 的工作原理：** 当 Claude 遇到任务时，会扫描可用的 Skills 以找到相关匹配项。Skills 采用渐进式信息披露机制：首先加载元数据（约 100 个 token），仅提供足够的信息让 Claude 判断该 Skill 是否适用；当确认相关时再加载完整指令（小于 5k token）；最后仅在需要时加载捆绑的文件或脚本。

**何时使用 Skills：** 当你需要 Claude 持续高效地执行专业任务时选择 Skills，适合以下场景：

- **组织工作流**：品牌规范、合规流程、文档模板
- **领域专长**：Excel 公式、PDF 处理、数据分析
- **个人偏好**：笔记系统、编码风格、研究方法

**示例：** 创建一个品牌规范 Skill，包含公司的色彩方案、字体规则和版式规范。当 Claude 创建演示文稿或文档时，会自动应用这些标准，无需每次重新说明。

---

### 什么是提示词（Prompts）？

提示词是你在对话过程中以自然语言向 Claude 提供的指令。它们是即时的、对话式的、响应性的——你在当下提供上下文和方向。

**何时使用提示词：**

- 一次性请求："总结这篇文章"
- 对话式调整："让语气更专业一些"
- 即时上下文："分析这些数据并识别趋势"
- 临时指令："将这些内容格式化为项目列表"

**小技巧：** 提示词是与 Claude 交互的主要方式，但不会跨对话保留。对于重复性工作流或专业知识，考虑将提示词封装为 Skills 或项目指令。

**何时改用 Skill：** 如果你发现自己在多次对话中反复输入相同的提示词，是时候创建一个 Skill 了。将"按照 OWASP 标准审查代码安全漏洞"或"按执行摘要、关键发现和建议格式化分析"等反复使用的指令转化为 Skills，既省去重复说明的麻烦，又能保证执行一致性。

---

### 什么是 Projects（项目）？

[Projects](https://support.claude.com/en/articles/9517075-what-are-projects) 适用于所有付费 Claude 计划，是拥有独立聊天历史和知识库的自包含工作区。每个项目包含 200K 上下文窗口，你可以上传文档、提供背景信息，并设置适用于该项目所有对话的自定义指令。

**Projects 的工作原理：** 你上传到项目知识库的所有内容，在该项目的所有对话中均可访问。Claude 会自动利用这些上下文提供更有针对性的回答。当项目知识接近上下文限制时，Claude 会无缝启用检索增强生成（RAG）模式，将容量扩展至最多 10 倍。

**何时使用 Projects：**

- **持久上下文**：应贯穿每次对话的背景知识
- **工作区组织**：为不同项目创建独立上下文
- **团队协作**：共享知识和对话历史（适用于 Team 和 Enterprise 计划）
- **自定义指令**：项目专属的语气、视角或处理方式

**示例：** 创建"Q4 产品发布"项目，上传市场调研、竞品分析和产品规格。该项目中的每次对话都可以访问这些知识，无需重复上传或说明。

**何时改用 Skill：** Projects 为特定工作提供持久上下文——公司代码库、研究项目、持续进行的客户业务。Skills 则是教 Claude **如何做某件事**。一个项目可能包含产品发布的所有背景信息，而 Skill 则可以教 Claude 团队的写作规范或代码审查流程。如果你发现自己在多个项目中复制相同的指令，这正是创建 Skill 的信号。

### 什么是子智能体（Subagents）？

[子智能体](https://docs.claude.com/en/docs/claude-code/sub-agents)是拥有独立上下文窗口、自定义系统提示和特定工具权限的专业 AI 助手。在 Claude Code 和 Claude Agent SDK 中，子智能体独立处理离散任务并将结果返回给主智能体。

**子智能体的工作原理：** 每个子智能体都有自己的配置——你定义它的职责、解决问题的方式，以及它可以访问的工具。Claude 会根据子智能体的描述自动将任务委派给合适的子智能体，你也可以明确指定使用特定子智能体。

**何时使用子智能体：**

- **任务专业化**：代码审查、测试生成、安全审计
- **上下文管理**：保持主对话专注，同时将专业工作分流
- **并行处理**：多个子智能体可同时处理不同方面
- **工具限制**：将特定子智能体限制为安全操作（如只读访问）

**示例：**

```
创建一个 code-reviewer 子智能体，赋予其 Read、Grep 和 Glob 工具访问权限，
但不赋予 Write 或 Edit 权限。当你修改代码时，Claude 自动将其委派给该子智能体
进行质量和安全审查，而不会冒意外修改代码的风险。
```

**何时改用 Skill：** 如果多个智能体或对话需要相同的专业知识——比如安全审查流程或数据分析方法——创建一个 Skill，而不是将该知识内置到单独的子智能体中。Skills 具有可移植性和可复用性，而子智能体则是为特定工作流定制构建的。用 Skills 传授任何智能体都能应用的专业知识；当你需要具有特定工具权限和上下文隔离的独立任务执行时，使用子智能体。

### 什么是 MCP？

模型上下文协议（MCP）是连接 AI 助手与外部系统的开放标准，这些外部系统包括内容仓库、业务工具、数据库和开发环境等数据存储位置。

**MCP 的工作原理：** MCP 提供了一种将 Claude 连接到工具和数据源的标准化方式。无需为每个数据源构建自定义集成，只需针对单一协议进行开发。MCP 服务器暴露数据和能力；MCP 客户端（如 Claude）连接到这些服务器。

**何时使用 MCP：** 当你需要 Claude 进行以下操作时选择 MCP：

- 访问外部数据：Google Drive、Slack、GitHub、数据库
- 使用业务工具：CRM 系统、项目管理平台
- 连接开发环境：本地文件、IDE、版本控制
- 集成自定义系统：你的专有工具和数据源

**示例：** 通过 MCP 将 Claude 连接到公司的 Google Drive。现在 Claude 可以搜索文档、读取文件，并引用内部知识，无需手动上传——连接持续存在并自动更新。

**何时改用 Skill：** MCP 将 Claude 连接到数据；Skills 教 Claude 如何处理这些数据。如果你在说明**如何使用**某个工具或遵循某个流程——比如"查询数据库时，始终先按日期范围过滤"或"用这些特定公式格式化 Excel 报告"——那是 Skill。如果你需要 Claude **访问**数据库或 Excel 文件，那是 MCP。两者结合使用：MCP 负责连接，Skills 负责流程知识。

## 它们如何协同工作

真正的威力在于将这些模块组合使用。每个模块都有其独特用途，组合起来可以构建复杂的智能体工作流。

### 对比：选择正确的工具

| 功能 | Skills | 提示词 | Projects | 子智能体 | MCP |
|------|--------|--------|----------|----------|-----|
| **提供什么** | 流程知识 | 即时指令 | 背景知识 | 任务委派 | 工具连接 |
| **持久性** | 跨对话 | 单次对话 | 项目内 | 跨会话 | 持续连接 |
| **包含内容** | 指令 + 代码 + 资源 | 自然语言 | 文档 + 上下文 | 完整智能体逻辑 | 工具定义 |
| **加载时机** | 按需动态加载 | 每轮对话 | 项目内始终加载 | 调用时 | 始终可用 |
| **能否包含代码** | 是 | 否 | 否 | 是 | 是 |
| **最适合** | 专业知识 | 快速请求 | 集中化上下文 | 专业任务 | 数据访问 |

### 示例智能体工作流：研究智能体

以下示例展示如何组合多个构建模块，构建一个用于竞品分析的综合研究智能体。

**第一步：创建 Project**

创建"竞争情报"项目，上传以下内容：
- 行业报告和市场分析
- 竞品产品文档
- 来自 CRM 的客户反馈
- 以往研究摘要

添加项目指令：

> 从我们的产品战略视角分析竞争对手。关注差异化机会和新兴市场趋势。以具体证据和可操作建议呈现研究结果。

**第二步：通过 MCP 连接数据源**

启用以下 MCP 服务器：
- Google Drive（访问共享研究文档）
- GitHub（查看竞品开源仓库）
- 网络搜索（获取实时市场信息）

**第三步：创建专业 Skills**

创建"竞品分析"Skill，定义公司 Google Drive 的导航策略、文件结构说明及搜索最佳实践，使 Claude 能高效定位内部文档和战略资料。

**第四步：配置子智能体（仅限 Claude Code/SDK）**

创建专业子智能体：

`market-researcher` 子智能体（配备 Read、Grep、Web-search 工具）：专注于市场趋势研究，收集量化数据（市场份额、增长率、融资情况）并综合分析行业动态。

`technical-analyst` 子智能体（配备 Read、Bash、Grep 工具）：专注于分析竞品技术架构、实现方式和工程决策，提供可指导产品决策的技术洞察。

**第五步：激活研究智能体**

当你向 Claude 提问："分析我们排名前三的竞争对手如何定位其新 AI 功能，并找出我们可以利用的差距"时，以下事情会依次发生：

1. **Project 上下文加载**：Claude 访问你上传的研究文档并遵循项目指令
2. **MCP 连接激活**：Claude 在 Google Drive 中搜索最新竞品简报，并获取 GitHub 数据
3. **Skills 介入**：竞品分析 Skill 提供分析框架
4. **子智能体执行**（在 Claude Code 中）：market-researcher 收集行业数据，technical-analyst 审查技术实现
5. **提示词精炼**：你提供对话式引导："重点关注医疗行业的企业客户"

**结果：** 一份综合竞品分析报告，汇集多个数据源，遵循你的分析框架，运用专业知识，并在整个研究项目中保持上下文连贯。

## 常见问题

### Skills 的工作原理是什么？

Skills 采用[渐进式信息披露](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)机制，保持 Claude 的高效运行。处理任务时，Claude 首先扫描 Skill 元数据（描述和摘要）识别相关匹配项；若匹配，则加载完整指令；最后，若 Skill 包含可执行代码或参考文件，仅在需要时加载这些内容。

这种架构意味着你可以拥有大量可用的 Skills，而不会占满 Claude 的上下文窗口。Claude 在需要时精确访问所需内容。

### Skills vs 子智能体：何时用哪个？

**使用 Skills 的情况：** 你希望任何 Claude 实例都能加载和使用的能力。Skills 类似培训材料——它们让 Claude 在所有对话中都能更好地完成特定任务。

**使用子智能体的情况：** 你需要完整的、为特定目的构建的自包含智能体，能够独立处理工作流。子智能体类似有着自己上下文和工具权限的专业员工。

**两者结合使用的情况：** 当你希望子智能体具备专业知识时。例如，代码审查子智能体可以使用 Skills 获取特定编程语言的最佳实践，将子智能体的独立性与 Skills 的可移植专业知识结合起来。

### Skills vs 提示词：何时用哪个？

**使用提示词的情况：** 你在给出一次性指令、提供即时上下文，或进行对话式交流。提示词是响应式的、临时的。

**使用 Skills 的情况：** 你有需要反复使用的流程或专业知识。Skills 是主动的——Claude 知道何时应用它们——并且跨对话持久存在。

**两者结合使用：** 提示词和 Skills 天然互补。使用 Skills 提供基础专业知识，使用提示词为每项任务提供具体上下文和精细调整。

### Skills vs Projects：何时用哪个？

**使用 Projects 的情况：** 你需要应用于特定工作所有对话的背景知识和上下文。Projects 提供始终加载的静态参考资料。

**使用 Skills 的情况：** 你需要仅在相关时才激活的流程知识和可执行代码。Skills 提供按需加载的动态专业知识，节省上下文窗口空间。

**两者结合使用的情况：** 当你同时需要持久上下文和专业能力时。例如，包含产品规格和用户研究的"产品开发"项目，结合用于创建技术文档和分析用户反馈数据的 Skills。

**核心区别：** Projects 说的是"这是你需要了解的内容"。Skills 说的是"这是如何完成某件事"。Projects 提供你在其中工作的知识库，Skills 提供在任何地方都能使用的能力——任何对话、任何项目。

### 子智能体可以使用 Skills 吗？

可以。在 Claude Code 和 Agent SDK 中，子智能体可以像主智能体一样访问和使用 Skills。这创造了强大的组合：专业子智能体利用可移植的专业知识。

例如，你的 python-developer 子智能体可以使用 pandas-analysis Skill，按照团队惯例执行数据转换；你的 documentation-writer 子智能体可以使用 technical-writing Skill，一致地格式化 API 文档。
